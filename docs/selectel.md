# Selectel S3: ключ только на чтение для бэкапа

Бэкап только читает бакет, поэтому и ключ ему лучше дать такой, который ничего не может записать или удалить.
У Selectel нет отдельной роли «только чтение для S3»: роль `reader` даёт просмотр в панели, но не доступ по S3 API.
Чтение без записи настраивается так: сервисный пользователь с ролью `s3.bucket.user` и политика доступа бакета,
которая разрешает ему только чтение.

Документация Selectel: [управление доступом в S3](https://docs.selectel.ru/s3/about/manage-access/),
[роли](https://docs.selectel.ru/access-control/role-reference/),
[политика доступа бакета](https://docs.selectel.ru/s3/buckets/bucket-policy/about-bucket-policy/).

## Сначала прочитайте

**Политика бакета действует на всех.** Пока у бакета нет политики, доступ определяет только роль пользователя. Как
только политика появляется, всё, что она не разрешает, запрещено пользователям с ролями `s3.user`,
`s3.bucket.user` и `object_storage_user`. Если у бакета уже есть другие пользователи с такими ролями (например,
ключ вашего приложения), их нужно разрешить в той же политике, иначе приложение потеряет доступ.

Поэтому:
1. Узнайте, какая роль у пользователя, чьи ключи использует приложение (верхнее меню «IAM» → пользователь).
2. Если бакетов несколько и один тестовый, настройте сначала его и проверьте, что приложение по-прежнему
   загружает и отдаёт файлы. Потом рабочий.
3. Публичный доступ к бакету (раздача файлов по ссылке или через CDN) после изменения тоже проверьте.

## 1. Сервисный пользователь

Верхнее меню панели «IAM» → сервисные пользователи → добавить. Имя, например, `s3-backup`. Роль:
`s3.bucket.user`, область — проект, в котором лежат бакеты (он выбран слева вверху на странице «Продукты» → «S3»).
Пароль ему не нужен.

## 2. S3-ключ

«Продукты» → «S3» → в меню слева «S3-ключи»: выпустите ключ этому пользователю для того же проекта. Панель покажет Access key и Secret key, секретный ключ
— один раз. Сразу положите их в файлы на сервере бэкапа (`secrets/<источник>_access_key`,
`secrets/<источник>_secret_key`, права 600), как в [README](../README.md#install): никуда больше их не
копируйте.

## 3. Политика бакета

В каждом бакете, который бэкапится: «Продукты» → «S3» → «Бакеты» → бакет → политика доступа. Правило для пользователя
`s3-backup`, ресурс — весь бакет, действия:

- `s3:ListBucket` — список объектов;
- `s3:GetObject` — чтение объекта.

И больше ничего. Если в бакете работают другие пользователи с ролями `s3.user` или `s3.bucket.user` (см. «Сначала
прочитайте»), добавьте в ту же политику правила для них с теми действиями, которые им нужны.

## 4. Проверка

В `.env` бэкапа для этого источника: `<ИМЯ>_ENDPOINT=https://s3.<пул>.storage.selcloud.ru` (например,
`s3.ru-3.storage.selcloud.ru`), `<ИМЯ>_REGION=<пул>` (например, `ru-3`), `<ИМЯ>_PATH_STYLE=yes`. Затем один
прогон:

```sh
docker exec s3-backup backup.sh run <источник>
```

Прогон должен закончиться строкой `[<источник>] done: bucket N objects …`. `AccessDenied` в логе значит, что
политика не разрешает пользователю `ListBucket` или `GetObject` для этого бакета.

Проверять запись этим ключом не нужно: бэкап в бакет никогда не пишет.
